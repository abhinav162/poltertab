The problem

Headless browsers are logged out of everything.

Every browser automation tool starts the same way: a fresh browser with no cookies, no sessions, no history. The first thing your agent hits is a login wall, then a CAPTCHA, then two-factor. PolterTab skips all of it. The agent works inside the Chrome you already use — the dashboards you're signed into, the tools your company runs, the tabs you already have open. If you can see it in your browser, your agent can work with it.

How it works

Four hops, all on your machine.

The agent speaks MCP (Model Context Protocol — the standard AI tools use to call external tools) to a small Node server on your machine. The server talks to the Chrome extension over a localhost WebSocket. The extension does the clicking, typing, and reading. Nothing leaves your computer.

01

Your AI agent

Any MCP client. Speaks MCP over stdio.

02

PolterTab MCP server

A local Node.js process. Connects over a WebSocket on localhost:7822.

03

PolterTab extension

Runs the commands using Chrome APIs and the DOM.

04

Your Chrome profile

The browser you already have open, signed in.

Several agents can share one browser with zero configuration: the first server to claim port 7822 serves the extension, later ones proxy through it, and each agent keeps its own current tab.

Security & privacy

Your browser stays yours.

Local only

The agent, the MCP server, and the extension all run on your machine. Page content travels over a localhost WebSocket — there are no PolterTab servers, and nothing is sent to us. Ever.

No telemetry

The only outbound call the server makes is a version check to registry.npmjs.org, at most once a day. Set POLTERTAB_NO_UPDATE_CHECK=1 to turn even that off.

Uploads refused by default

browser_upload_file only accepts files from folders you've listed in ~/.poltertab/config.json. Sensitive paths (~/.ssh, ~/.aws, ~/.gnupg, system directories, home dotfiles) are blocked even if you allowlist them.

Open source

The whole thing — extension and server — is on GitHub. The npm package is published with provenance, so you can verify what you installed is what's in the repo.

You can see it working

The agent acts in your visible browser, in a "PolterTab" tab group. Close the tab, and it's over.

Works with

Any MCP client.

Claude Code, Claude Desktop, Cursor, or anything else that speaks MCP — including agents you build yourself. poltertab setup registers the server with Claude Code automatically; for other clients, add one entry to their MCP config.

Install

Install in two steps.

Requires Node 18 or newer.

1

The server

npm install -g poltertab
poltertab setup

The wizard installs the MCP registration, a browser-navigation skill, and a CLAUDE.md note so your agent knows the tools exist. Safe to re-run.

2

The extension

  1. Download the latest release zip.
  2. Unzip it into its own folder (double-clicking on macOS makes one).
  3. Open chrome://extensions/ and enable Developer mode.
  4. Click Load unpacked and select that folder — the one containing manifest.json.
  5. Restart your AI tool.
FAQ

Questions

Does PolterTab send my browsing data anywhere?

No. Everything runs locally: agent → local server → extension, over stdio and a localhost WebSocket. The one outbound request the server makes is a daily version check to npm's registry, and POLTERTAB_NO_UPDATE_CHECK=1 disables it. The extension makes no outbound requests at all.

Can the agent read my passwords or cookies?

It can't read your password manager or Chrome's cookie store. It sees what a script running in a page can see: the rendered page, and the network responses that page loads. It acts with your session — that's the point — but credentials themselves are never read or transmitted.

Can the agent upload any file from my disk?

No. Uploads are refused unless the file lives in a folder you've explicitly listed in ~/.poltertab/config.json (upload_allowed_paths). Directories like ~/.ssh, ~/.aws, and system paths are blocked regardless of the allowlist.

What about sites that fight automation?

That's the specialty. browser_smart_scroll handles virtualized and infinite-scroll pages, browser_get_network_state captures the API/GraphQL responses behind an obfuscated DOM, and site memory stores per-domain obstacles and fixes so the agent doesn't re-learn a hostile site every session.

Can multiple agents use the same browser?

Yes. The first MCP server to bind the port becomes primary; later ones proxy through it automatically. Each agent gets its own current tab. Up to 50 agents can share one browser.

Is it open source?

Yes — extension and server, on GitHub. npm releases are published with provenance. ISC license.

Why does the extension need the debugger permission?

Only for file uploads via the OS file picker: Chrome's DevTools Protocol is the only way to intercept a page's file-chooser dialog. The debugger is attached to one tab for the duration of the upload and detached after — Chrome shows a banner while it's attached, so you always know.
