04 · on your machine

Four hops, all on your machine.

Your agent speaks MCP (Model Context Protocol) to a small Node server. The server relays each command to the Chrome extension over a WebSocket on localhost:7822, open only to this machine. The extension clicks, types and reads; the result travels the same path back.

Several agents can share one browser. The first server to claim the port serves the extension; up to 50 more proxy through it, each with its own tab.

  1. Your AI agentAny MCP client, speaking over stdio.
  2. PolterTab serverA local Node.js process. localhost:7822 →
  3. PolterTab extensionRuns the commands with Chrome APIs and the DOM.
  4. Your ChromeThe profile you’re signed into, in the window you can see. ← back, same path

The whole thing makes one network call.

A version check against registry.npmjs.org, at most once a day, cached locally.

  • POLTERTAB_NO_UPDATE_CHECK=1 turns it off.
  • poltertab setup looks up the Chrome Web Store version once, to warn when extension and server disagree.
  • The extension makes no outbound requests at all.
  • Verify it in the source: the check lives in one small file.

  • No PolterTab servers

    Agent, server and extension all run on your machine; page content moves between them over localhost. There are no PolterTab servers to send data to.

  • Uploads need an allowlist

    browser_upload_file accepts a file only from a folder you wrote into ~/.poltertab/config.json. ~/.ssh, ~/.aws, ~/.gnupg and system directories stay blocked even inside an allowlisted folder.

  • You can watch it work

    The ghost acts in your visible browser, inside a tab group labeled “PolterTab”. You can follow every click, and you can close the tab mid-task.

  • Audit it, don’t trust it

    Extension and server are open source under ISC. npm builds carry provenance, tying the package you installed to the commit it was built from.

Install in two steps.

Node 18 or newer.

  1. Step 1: the server

    Install and run setup

    npm install -g poltertab poltertab setup

    Setup takes about 5 seconds: it registers the MCP server, installs a browser-navigation skill and adds a CLAUDE.md note so your agent knows the tools exist. Re-running it is safe.

    Using Cursor? Add the server in one click: Add to Cursor

  2. Step 2: the extension

    Add it to Chrome

    Install it from the Chrome Web Store. Chrome keeps it up to date on its own.

    Add to Chrome

    Then restart your AI tool so it sees the new tools.

    Developer or offline? Load the unpacked zip instead.
    1. Download the latest release zip and unzip it.
    2. Open chrome://extensions/ and switch on Developer mode.
    3. Click “Load unpacked” and pick the unzipped folder, the one containing manifest.json.
    4. Restart your AI tool.

    An unpacked extension never updates on its own; reload it from a newer zip yourself.

Fair questions.

Does PolterTab send my browsing data anywhere?

No. Commands and page content travel from agent to server to extension over stdio and a localhost WebSocket. The server’s only outbound request is the daily version check, and POLTERTAB_NO_UPDATE_CHECK=1 disables it.

Can the agent read my passwords or cookies?

It can’t open your password manager or Chrome’s cookie store. It sees what a page script sees: the rendered page and its network responses. It acts with your session, but the credentials behind it are never read or transmitted.

Can the agent upload any file from my disk?

Only from folders listed in ~/.poltertab/config.json under upload_allowed_paths. Everything else is refused; ~/.ssh and ~/.aws are refused even inside a listed folder.

What about sites that fight automation?

browser_smart_scroll walks virtualized and infinite-scroll pages. browser_get_network_state captures the API and GraphQL responses behind an obfuscated DOM. Site memory keeps per-domain notes, so a hostile site is learned once.

Can several agents share one browser?

Yes, up to 50 plus the primary. The first server to bind the port coordinates; later ones proxy through it automatically, and each agent gets its own current tab.

Why does the extension need the debugger permission?

For one feature: file uploads through the OS file picker, which only Chrome’s DevTools Protocol can intercept. It attaches to one tab for the upload, detaches after, and Chrome shows its banner the whole time.

Is it open source?

Yes, extension and server both, under ISC. npm releases are published with provenance.
